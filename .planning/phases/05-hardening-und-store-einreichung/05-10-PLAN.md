## Phase Goal

**Als** Administrator, der die App im Nextcloud App Store findet, **moechte ich** die Fassung installieren, die per Klick funktioniert und sich restlos entfernen laesst, **damit** der Store-Eintrag haelt, was diese Phase gebaut hat.

Quelle: Requirement EXAPP-04 in seinem Pflegeteil, plus 05-RESEARCH Open Question 1 mit ihrer Empfehlung (nicht zurueckziehen, sondern das Ein-Klick-Problem loesen und als Folgerelease nachschieben).

<objective>
Das Folgerelease 0.1.1 herausbringen und den Store-Eintrag auf den Stand dieser Phase heben, mit einem Runbook, das den naechsten Durchgang ohne Recherche moeglich macht.

Purpose: Erfolgskriterium 1 ist seit dem 19.08.2026 erfuellt, `mcp_connector` 0.1.0 ist live im Store, an zwei unabhaengigen Stellen geprueft. Was die gelistete Version nicht hat, sind die Ergebnisse dieser Phase: die Admin-Einstellungen, den Setup-Zustand statt des Startabbruchs, die Schalter-Durchsetzung und das Purge-Kommando. Ein Admin, der heute per Klick installiert, bekommt eine Installation, die ohne Umgebungsvariablen nicht startet. Genau das behebt dieses Release.
Output: die Versionsanhebung, ein CHANGELOG-Eintrag, das ergaenzte Runbook, der Live-Nachweis nach dem Upload.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lokaler Signaturschluessel zu Store | Der private Schluessel bleibt beim Owner; der Store prueft die Signatur beim Upload |
| GitHub Release Asset zu jeder fremden Instanz | AppAPI laedt das Archiv zur Installationszeit von dieser URL und prueft die Signatur erneut |
| ghcr.io zu Deploy Daemon | Das Image wird anonym gezogen; der Tag entscheidet, welche Fassung laeuft |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-45 | Tampering | Auseinanderlaufende Werte von version, Git-Tag und image-tag | mitigate | Gleichheit von version und image-tag im verify-Kommando maschinell geprueft; das Runbook macht den Tag zum dritten identischen String und nennt die Folge einer Abweichung |
| T-05-46 | Denial of Service | Geloeschtes Release-Asset oder umgeschriebener Tag bricht die Installation bei fremden Admins | mitigate | Warnblock im Runbook, plus die `curl -I`-Pruefung nach jedem Release als Pflichtschritt |
| T-05-47 | Information Disclosure | Signaturschluessel oder Store-Zugangsdaten im Repo, im Log oder im Protokoll | mitigate | Beide bleiben beim Owner; der Checkpoint verlangt ausdruecklich nur Statuscode und Workflow-URL zurueck, nie einen Schluessel oder eine Signatur |
| T-05-48 | Tampering | Ein Update loescht die bestehenden Verbindungen | mitigate | Nachweis in Task 3 auf einer Instanz mit vorhandener Verbindung; der `enabled=0`-Hook raeumt nichts auf (Plan 05-06, T-05-28) |
| T-05-SC | Tampering | npm-, pip- oder cargo-Installationen | accept | Keine Installation; `uv.lock` unveraendert, per `git diff --stat` geprueft |
</threat_model>
