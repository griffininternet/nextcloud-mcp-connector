  <action>
    Lege `def loopback_match(requested: str, registered: Sequence[str]) -> str | None` neben
    `redirect_uri_allowed`. Sie liefert die registrierte Adresse, auf die die angefragte
    passt, wenn der Port ausser Acht bleibt, und sonst `None`.

    Regeln, jede einzeln begruendet im Docstring:
    - Die Funktion ist nur fuer Loopback zustaendig. Ist der Host der angefragten Adresse
      nicht in `LOOPBACK_HOSTS`, ist das nicht ihre Sache und die Antwort ist `None`.
      `LOOPBACK_HOSTS` ist die konsistente Menge, weil D-35 genau diese drei Hosts schon als
      registrierbar zulaesst; eine buchstabengetreue Umsetzung nur fuer IP-Literale liesse
      Claude Code draussen, das zur Laufzeit `localhost` schickt.
    - Verglichen wird exakt: Schema, Host (case-insensitiv wie bei `redirect_uri_allowed`),
      Pfad und Query muessen gleich sein. Nur der Port ist frei. Ein Host-Wechsel ist kein
      Port-Wechsel.
    - Fragment, Userinfo und ein unparsbarer Host oder Port sind Absagen, mit demselben
      `try/except ValueError` um `hostname`/`port` wie im Nachbarn.
    - Der geprueft Wert wird nicht geloggt.
    - Anti-Pattern, das der Docstring benennt: die angefragte Adresse beim Fund in die
      `redirect_uris` des Clients schreiben. Das machte aus einem Vergleich eine
      Registrierung, liesse die Zeile bei jedem Lauf wachsen und gaebe einem Angreifer mit
      einem Loopback-Port eine dauerhafte Eintragung.

    Der Docstring nennt die Norm mit Fundstelle (RFC 8252 Abschnitt 7.3, "MUST allow any port
    to be specified at the time of the request for loopback IP redirect URIs") und den
    gemessenen Grund (Claude Code veroeffentlicht `http://localhost/callback` und kommt mit
    `http://localhost:3118/callback`). `loopback_match` kommt alphabetisch in `__all__`.
  </action>

    `registry.loopback_match(str(requested), [str(u) for u in client.redirect_uris or []])`
    befragt. Liefert sie eine registrierte Adresse, gilt der Vergleich als bestanden und die
    ANGEFRAGTE Adresse (mit ihrem Port) ist die weiterverwendete `address`; liefert sie
    `None`, bleibt es beim bisherigen `E5`.

    Zwei Muster dieser Datei sind bindend:
    1. Die Reihenfolge. Die Pruefung `redirect_uri_allowed(str(address))` danach bleibt
       stehen und wird auf die angefragte Adresse angewandt: eine Lockerung des Ports darf
       die D-35-Pruefung des Ergebnisses nicht ueberspringen (T-03-41).
    2. Ein Fehlerbild fuer alles. Es entsteht kein neuer Fehlercode und keine Auskunft
       darueber, welche Pruefung fiel; `E5` bleibt die Antwort, weil eine Antwort, die die
       Faelle trennt, ein Informationsdienst fuer den Ratenden ist (T-03-47).

    Auth-Code geht. Das ist die Voraussetzung dafuer, dass der SDK-Token-Endpunkt ohne
    Aenderung stimmt: er vergleicht gegen den gespeicherten Wert. Der Kommentar an der Stelle
    sagt das mit Fundstelle (`mcp/server/auth/handlers/token.py:164-183`), damit niemand
    spaeter eine zweite Lockerung im Token-Pfad einbaut.

    Nichts wird in `client.redirect_uris` geschrieben (Anti-Pattern aus Task 2).
