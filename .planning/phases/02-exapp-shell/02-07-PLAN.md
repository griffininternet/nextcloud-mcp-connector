Aus 02-RESEARCH.md, Abschnitt "Enge Routen-Deklaration und ihre Wirkung":

Die vollstaendige Kette fuer einen echten Aufruf:

```
Client: POST http://127.0.0.1:8081/exapps/mcp_connector/mcp   (Basic <alice:app-passwort>)
HaRP:   Route ^/mcp/?$ trifft, access_level USER
        nc_get_user -> GET /index.php/apps/app_api/harp/user-info
        -> user_id "alice"
        AUTHORIZATION-APP-API = b64("alice:<secret>")
ExApp:  verify_appapi_headers -> "alice"
        Credentials(mode="appapi", user="alice", secret=APP_SECRET)
        -> Anfrage an Nextcloud mit den vier Headern
Nextcloud: setUser(alice) -> alices ACLs greifen
```

Damit loest HaRP die Nutzeridentitaet aus einem gewoehnlichen App-Passwort auf. Der Client braucht dafuer kein OAuth; das ist der Grund, warum die Permission-Parity in Phase 2 bereits vollstaendig beweisbar ist (02-RESEARCH.md, "Wichtiger Nebenbefund fuer die Reihenfolge").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP-Client zu HaRP | Ein beliebiger Client sendet Anmeldedaten eines Nextcloud-Nutzers an eine oeffentlich erreichbare Route |
| HaRP zu ExApp | HaRP entscheidet, welcher Nutzer wir sind; die ExApp glaubt ausschliesslich dem gesetzten Header |
| ExApp zu Nextcloud | Impersonation; die ACLs bleiben serverseitig |
| Dokumentation zu Betreibern | Eine falsche Anleitung erzeugt eine falsch konfigurierte Instanz |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-60 | Elevation of Privilege | Ein Nutzer sieht ueber MCP Daten eines anderen Nutzers | mitigate | Lecktests fuer files, notes, unified_search und den Direktzugriff bei bekanntem Pfad, jeweils mit Positivkontrolle im selben Lauf; ein 200 auf einem Lecktest faerbt rot |
| T-02-61 | Spoofing | Falsch positiver Parity-Beweis durch zwei identische Fixtures | mitigate | Guard-Test vor allen Lecktests, uebernommen aus dem Phase-1-Analog |
| T-02-62 | Information Disclosure | Anleitung empfiehlt eine unsichere Konfiguration | mitigate | Jede Aussage in docs/client-setup.md ist entweder gemessen oder verweist auf das Dokument mit der Messung; die Stolperstellen benennen den Reverse-Proxy und den Discovery-Pfad ausdruecklich |

| T-02-64 | Denial of Service | Abnahme deaktiviert die App und laesst sie deaktiviert zurueck | accept | Der Checkpoint verlangt Deaktivieren und Wiederaktivieren als Paar; die Topologie ist eine Wegwerf-Instanz auf Loopback |
