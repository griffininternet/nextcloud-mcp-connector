## Phase Goal

**Als** Nextcloud-Administrator **moechte ich** die MCP-App als ExApp ueber AppAPI installieren, **damit** meine Nutzer ihren KI-Assistenten mit ihrer eigenen Identitaet an die Cloud anbinden und dabei nie mehr sehen als in der Weboberflaeche.

Dieser Plan entscheidet die Frage, an der Phase 3 haengt: kommt ein OAuth-faehiger Client von aussen an die Discovery-Metadaten dieser ExApp heran, und ueber welchen Pfad.

<objective>
Den Discovery-Spike (AUTH-06) fahren und als eigenstaendiges Dokument abschliessen: Metadaten unauthentifiziert erreichbar, WWW-Authenticate unveraendert beim Client, Wurzelpfad-Befund, Streaming-Nachweis, Empfehlung und Fallback fuer Phase 3.

Output: Metadaten-Route plus Messsonde in der ExApp, ein wiederholbares Messskript, docs/spike-discovery.md.
</objective>

Aus 02-RESEARCH.md, Abschnitt "Der Discovery-Spike (AUTH-06): Go-Kriterien und Belege" sowie "Pitfall 1", "Pitfall 4", "Pitfall 6":

Bereits ohne Messung belegt (Quellcode beider Seiten):

- `access_level` PUBLIC heisst woertlich "public access without auth"; HaRP laesst solche Routen vor jeder Nutzerpruefung durch, der PHP-Proxy-Controller ist `#[PublicPage] #[NoCSRFRequired]`
- Der Antwort-Filter des PHP-Proxys entfernt nur `aa-version`, `ex-app-id`, `authorization-app-api`, `ex-app-version` und `aa-request-id`; `WWW-Authenticate` bleibt also erhalten
- In Nextcloud AIO routet der mitgelieferte Caddy `/exapps/*` ab Werk an HaRP
- Streamable HTTP streamt laut AppAPI-Maintainer durch HaRP unveraendert durch (app_api#825)

Was gemessen werden muss:

1. `curl -i <base>/exapps/mcp_connector/.well-known/oauth-protected-resource/mcp` ohne Cookie und ohne Auth: erwartet 200 mit JSON
2. Ein Pfad, der einen 401 mit `WWW-Authenticate: Bearer resource_metadata="..."` erzeugt, unauthentifiziert von aussen: kommt der Header unveraendert beim Client an
3. Dieselben zwei Faelle ueber `<base>/apps/app_api/proxy/mcp_connector/...` (Zweitweg, PHP)
4. Der kanonische Wurzelpfad `<base>/.well-known/oauth-protected-resource/exapps/mcp_connector/mcp`: erwartet 404 von Nextcloud. Dieses Ergebnis ist der eigentliche Spike-Befund
5. Streaming-Nachweis: eine MCP-Session mit dem echten SDK-Client ueber den HaRP-Pfad

Randbedingungen, die die Messung praegen:

- Die ExApp kann ihre eigene oeffentliche URL nicht aus dem Request ableiten: das Praefix ist gestrippt, der Host gehoert dem Reverse-Proxy, `X-Forwarded-Prefix` gibt es nicht. Die URL kommt aus `NC_MCP_PUBLIC_URL` (existiert bereits in config.py als `public_url`).
- Auf einer PUBLIC-Route keinen `Authorization`-Header senden, wenn er nicht gebraucht wird: HaRP fragt sonst pro Request bei Nextcloud nach (Pitfall 6).
- Alle Antworten tragen `Cache-Control: no-store`, sonst cacht der PHP-Proxy JSON eine Stunde (Pitfall 4).
- Die deklarierte Route `^/\.well-known/` mit `access_level` PUBLIC und Verb GET deckt jeden Pfad unterhalb von `/.well-known/` ab. Fuer diesen Spike ist deshalb KEINE Aenderung an appinfo/info.xml noetig; jede Messsonde liegt unterhalb dieses Praefixes. `/mcp` bleibt in Phase 2 auf `USER`.

Vorhandene Bausteine:

- `config.public_url(env)` liefert die konfigurierte oeffentliche Basis-URL (config.py Z. 115-118)
- `entry_exapp.build_exapp_app(env)` haengt bereits `lifecycle_routes(env)` an; dasselbe Muster gilt fuer die Discovery-Routen
- `tests/compat/modern_client_check.py` nimmt eine URL als Argument, baut einen httpx-Client mit Basic-Header aus der Umgebung und fuehrt tools/list aus; Exit-Code 1 bei jedem Fehler
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet zu PUBLIC-Route | Eine unauthentifizierte Route ist per Definition von jedem erreichbar |
| Antwortinhalt zu Oeffentlichkeit | Alles, was die Metadaten-Route ausgibt, ist oeffentlich |
| Proxy zu Client (Antwortheader) | WWW-Authenticate und Cache-Control passieren zwei fremde Komponenten |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-40 | Information Disclosure | PUBLIC-Metadaten-Route gibt interne Details preis | mitigate | Antwort enthaelt ausschliesslich die konfigurierte oeffentliche URL und die Methodenliste; kein Hostname aus dem Request, keine Version, keine Konfiguration (T-01-29 analog); Feldmenge im Unit-Test geprueft |
| T-02-41 | Spoofing | Metadaten-URL aus dem Request abgeleitet (Host-Header-Injection) | mitigate | resource kommt ausschliesslich aus config.public_url; Grep-Gate gegen Zugriffe auf Host und Request-URL; Unit-Test mit fremdem Host-Header |
