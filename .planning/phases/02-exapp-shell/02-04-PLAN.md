**Als** Nextcloud-Administrator **moechte ich** die MCP-App als ExApp ueber AppAPI installieren, **damit** meine Nutzer ihren KI-Assistenten mit ihrer eigenen Identitaet an die Cloud anbinden und dabei nie mehr sehen als in der Weboberflaeche.

Dies ist der Plan, nach dem der erste Satz woertlich wahr ist: ein Admin installiert die App, und sie laeuft.

</objective>

occ-Kommandos, die den Ablauf tragen:

- `occ app:install app_api` (AppAPI ist nicht im Server-Tarball, braucht Netz; Pitfall 9)
- `occ app_api:daemon:register harp_proxy_docker "Harp Proxy (Docker)" docker-install http "appapi-harp:8780" "http://caddy" --net <compose-netz> --harp --harp_frp_address "appapi-harp:8782" --harp_shared_key "$HP_SHARED_KEY" --set-default`
- `occ app_api:app:register mcp_connector harp_proxy_docker --info-xml <pfad> --force-scopes` fuer den Container-Deploy
- `occ app_api:app:register mcp_connector manual_install --json-info '<json>' --force-scopes --wait-finish` fuer den Dev-Loop ohne Container; das JSON traegt Routen typisiert und ein festes `secret`
- `occ app_api:app:list` und `occ app_api:daemon:list` fuer die Verifikation

Zwingende Randbedingungen:

- Nextcloud muss die ExApp ueber die eigene oeffentliche URL erreichen (`<nextcloud_url>/exapps/<appid>`), also ueber den Reverse-Proxy. Ohne `/exapps/`-Regel scheitert bereits der Heartbeat mit "heartbeat check failed. Make sure that Nextcloud instance and ExApp can reach it other." (Pitfall 7).
- `nextcloud_url` bei `daemon:register` explizit setzen, sonst ersetzt AppAPI https durch http.
- `APP_SECRET` wird bei jeder Registrierung neu erzeugt; im manual-install-Dev-Loop deshalb ein festes `secret` im JSON vorgeben, sonst laeuft der lokale Prozess mit einem veralteten Secret (Pitfall 11).
- Ein Passwort fuer occ muss per `docker compose exec -e OC_PASS=...` in den Container reisen; eine auf dem Host gesetzte Variable erreicht ihn nie (Lehre aus Phase 1).

Caddyfile-Kern aus dem AIO-Original abgeleitet:

```
:80 {
    route /exapps/* { reverse_proxy appapi-harp:8780 { transport http { read_timeout 1800s } } }
    route { reverse_proxy nextcloud:80 }
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Entwicklerrechner zu Testtopologie | Vier Container mit Wegwerf-Zugangsdaten; jede veroeffentlichte Portzeile ist eine Exposition |
