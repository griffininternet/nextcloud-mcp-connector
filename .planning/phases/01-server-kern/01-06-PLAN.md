<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool-Parameter zu Notes-REST | Modellgenerierte Titel und Inhalte werden geschrieben |
| Unified-Search-Antwort zu ID-Bildung | Fremde resourceUrl wird zu einer internen ID |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-38 | Information Disclosure | Credentials in OCS-Fehlermeldungen | mitigate | Fehlertexte enthalten nur message und hint, nie Header, nie URLs mit Credentials; geerbte Maskierung aus Plan 02 |
| T-01-39 | Spoofing | SSRF ueber resourceUrl aus Suchergebnissen | mitigate | resourceUrl wird nur geparst, niemals abgerufen; Requests gehen ausschliesslich an die Basis-URL aus Env |
| T-01-40 | Tampering | Falsche ID-Aufloesung durch fremdes URL-Format | mitigate | Zentraler ids.py-Codec, Treffer ohne verwertbares Format werden uebersprungen statt geraten |
| T-01-41 | Tampering | Create-only-Verhalten bei notes_create | mitigate | Nur POST /notes, kein PUT, kein DELETE; Annotationen readOnly=False, destructive=False sind ehrlich, weil der Client keine Update-Funktion hat |
| T-01-42 | Elevation of Privilege | Confused Deputy ueber Nutzer-Parameter | mitigate | Kein Tool-Parameter enthaelt einen Nutzer; Identitaet aus deps.resolve_credentials |
| T-01-43 | Denial of Service | Grosse Notizinhalte sprengen den Client-Kontext | mitigate | limit im Search, exclude=content in der Liste, notes_read liefert eine einzelne Notiz |
| T-01-44 | Tampering | XML-Injection und Path Traversal | transfer | In diesem Plan gibt es kein XML und keinen Dateipfad; Kontrollen bleiben in Plan 02 und 05 |
</threat_model>
