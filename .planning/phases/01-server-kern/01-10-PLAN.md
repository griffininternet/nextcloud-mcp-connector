## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Suchbegriff zu OCS-Query | Modellgenerierter Text wird Query-Parameter |
| Fremde Provider-Antworten zu unserer Antwort | Inhalte und URLs aus beliebigen installierten Apps |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-68 | Spoofing | SSRF ueber resourceUrl fremder Provider | mitigate | resourceUrl wird nur geparst und ausgegeben, niemals abgerufen; alle Requests gehen an die Basis-URL aus Env |
| T-01-69 | Tampering | Falsche ID-Aufloesung fuehrt spaeter zum falschen Objekt | mitigate | provider_map plus zentraler ids-Codec, unbekannte Provider werden zu kind "url" statt geraten |
| T-01-70 | Information Disclosure | Berechtigungsverletzung durch eigenen Index | mitigate | Kein eigener Index, kein Caching von Ergebnissen; Nextcloud filtert serverseitig pro Nutzer |
| T-01-71 | Denial of Service | Ein haengender Provider blockiert den ganzen Aufruf | mitigate | asyncio.gather mit return_exceptions=True plus hartes Timeout pro Provider, degraded-Markierung |
| T-01-72 | Denial of Service | Sehr viele Provider erzeugen sehr grosse Antworten | mitigate | limit pro Provider, kompakte Felder, Server-Cursor statt vollstaendiger Listen |
| T-01-73 | Information Disclosure | Credentials in Fehlermeldungen | mitigate | Geerbte Kontrollen aus Plan 02, Provider-Fehler nennen nur Provider-Name und Grund |
| T-01-74 | Tampering | Create-only-Schreibschutz, Path Traversal, XML-Injection | transfer | Nur Lesepfade und keine Pfade beziehungsweise kein XML in diesem Plan; Kontrollen bleiben in Plan 02, 03 und 05 |
</threat_model>
