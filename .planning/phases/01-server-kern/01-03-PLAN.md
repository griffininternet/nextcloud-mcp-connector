  <behavior>
    - upload() auf einen freien Pfad liefert JSON mit path, etag, created=true
    - Antwortet Nextcloud mit 412, liefert das Tool "A file already exists at &lt;path&gt;. This server never overwrites files. Choose a different name."
    - 403 liefert einen Rechte-Hinweis, 404 nennt den fehlenden Elternordner ohne Auto-Mkcol
    - Pfad mit ".." wird abgelehnt, ohne dass ein Request stattfindet
    - Leerer content ist erlaubt, ein Nicht-UTF-8-Payload wird abgelehnt
  </behavior>
  <action>
    dav.py um put_new_file(client, creds, path, data, content_type) ergaenzen: PUT auf "&lt;base&gt;/remote.php/dav/files/&lt;user&gt;&lt;quoted path&gt;" mit Headern "If-None-Match: *" und Content-Type, Auth als httpx.BasicAuth pro Request. Status-Mapping: 412 -> ConflictError mit dem oben genannten Text, 403 -> Rechte-Hinweis, 404 -> fehlender Elternordner, 401 -> App-Passwort abgelehnt ohne Retry, sonst raise_for_status. X-NC-WebDAV-AutoMkcol wird bewusst NICHT gesetzt (Ordneranlage ist kein Teil des Tool-Vertrags). Kein PROPFIND-Existenzcheck vor dem PUT: der Schutz ist serverseitig und rennfrei.
    tools/files.py um async def upload(clients, path, content, content_type="text/markdown") ergaenzen: safe_path, UTF-8-Kodierung, Aufruf put_new_file, kompakte Antwort.
    server/reg_files.py um files_upload ergaenzen: @mcp.tool(annotations=CREATE_ONLY, structured_output=False) plus @graceful, Docstring einzeilig "Create a new text file. Fails if the target already exists; never overwrites."
    tests/unit/test_files_upload.py mit respx: alle Faelle aus dem behavior-Block, zusaetzlich die Pruefung, dass der Request den Header "If-None-Match: *" traegt.
    tests/integration/test_files_roundtrip.py mit @pytest.mark.integration, nutzt live_env aus tests/conftest.py: (1) Upload einer Datei mit Zeitstempel im Namen, (2) files_read liest denselben Inhalt zurueck, (3) zweiter Upload auf denselben Pfad erwartet die Konflikt-Meldung (das ist der A1-Beweis fuer TOOL-09), (4) files_read auf einen nicht existierenden Pfad liefert den not-found-Fehler. Die Tests laufen als alice, niemals als admin.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool-Parameter zu Nextcloud-Schreibpfad | Modellgenerierter Pfad und Inhalt landen in einem PUT |
| Bootstrap-Skript zu Test-Instanz | Admin-Kommandos erzeugen Testnutzer und App-Passwoerter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-15 | Tampering | Ueberschreiben bestehender Dateien via files_upload | mitigate | PUT ausschliesslich mit "If-None-Match: *", serverseitige Precondition in sabre/dav, 412 wird in eine erklaerende Meldung uebersetzt; Integrationstest belegt das Verhalten |
| T-01-16 | Elevation of Privilege | Path Traversal im Upload-Ziel | mitigate | safe_path() vor dem Requestbau, quote(path, safe="/"), Unit-Test ohne HTTP-Call |
| T-01-17 | Information Disclosure | App-Passwoerter aus dem Bootstrap im Repo | mitigate | .env.test in .gitignore, nur .env.test.example eingecheckt, Tests laufen als alice und bob, nie als admin |
| T-01-18 | Spoofing | SSRF ueber die Nextcloud-Basis-URL | mitigate | Basis-URL nur aus NC_MCP_URL, kein URL-Parameter im Tool, follow_redirects=False bleibt aktiv |
| T-01-19 | Tampering | Injection in WebDAV-XML | transfer | Dieser Plan sendet keinen XML-Body (PUT ist Rohinhalt). Kontrolle bleibt bei Plan 02 (lxml) und Plan 05 (SEARCH-Body) |
| T-01-20 | Denial of Service | Grosse Uploads binden Server und Nextcloud | accept | Der Inhalt kommt aus dem Client-Kontext und ist dadurch faktisch begrenzt; ein expliziter Upload-Cap ist v1.x, Risiko niedrig fuer Selfhoster |
</threat_model>
