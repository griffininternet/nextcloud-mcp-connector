- app = mcp.streamable_http_app() liefert eine Starlette-App mit Endpoint /mcp
- Ohne transport_security antwortet die App auf jeden fremden Host-Header mit 421 Misdirected Request
- Der SDK-Auth-Layer (BearerAuthBackend) akzeptiert ausschliesslich "Bearer "; Basic laeuft nie durch token_verifier

- stateless_http bleibt ungesetzt (Legacy-only-Knopf, #227-Falle)
- streamable_http_client(url, http_client=...) nimmt kein headers= mehr, Header gehoeren an den httpx2.AsyncClient

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet zu HTTP-Endpoint | Unauthentifizierte Requests treffen /mcp und /health |
| Authorization-Header zu Nextcloud | Client-gelieferte Credentials werden weitergereicht, nie als Identitaetsbehauptung geglaubt |
| Host-Header zu Transport-Layer | DNS-Rebinding-Vektor auf den lokalen Port |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-21 | Information Disclosure | Credentials im Authorization-Header | mitigate | Header wird nie geloggt, nie gecacht, nie in Fehlermeldungen wiederholt; Weitergabe ausschliesslich an die konfigurierte Nextcloud-Basis-URL; follow_redirects=False verhindert Header-Weitergabe an fremde Hosts |
| T-01-22 | Spoofing | DNS-Rebinding auf den MCP-Port | mitigate | TransportSecuritySettings mit expliziter Allowlist aus NC_MCP_ALLOWED_HOSTS, Test belegt 421 fuer fremde Hosts |
| T-01-23 | Elevation of Privilege | Header als Identitaetsbehauptung missverstehen | mitigate | Keine eigene Authentifizierung, keine Nutzerableitung aus dem Header fuer Autorisierungsentscheidungen; Nextcloud entscheidet, Kommentar im Code |
| T-01-24 | Spoofing | Static Bearer per Timing-Angriff erraten | mitigate | secrets.compare_digest, keine Teilvergleiche, kein Logging des Tokens |
| T-01-25 | Denial of Service | Brute-Force-Amplifikation ueber viele Nutzer hinter einer IP | mitigate | Kein Auth-Retry, 401 und 429 als Endzustand mit Handlungshinweis |
| T-01-26 | Tampering | Path Traversal und XML-Injection | transfer | Kontrollen liegen in Plan 02 (safe_path, lxml) und gelten unveraendert fuer den HTTP-Modus, weil derselbe Tool-Code laeuft |
| T-01-27 | Tampering | Create-only-Schreibschutz | transfer | Kontrolle liegt in Plan 03 (If-None-Match: *), transportunabhaengig |
| T-01-28 | Spoofing | SSRF ueber nutzergelieferte URL | accept | In Phase 1 existiert kein URL-holendes Tool; Basis-URL kommt aus Env. Als Nicht-Ziel dokumentiert |
| T-01-29 | Information Disclosure | /health gibt interne Details preis | mitigate | Antwort enthaelt nur status und Version, keine Konfiguration, keine Hostnamen |
</threat_model>
