# Phase 3: UI Design Contract

> Visual and interaction contract for the browser facing surface of the OAuth 2.1 phase.
> Generated by gsd-ui-researcher (--auto, no user questions), verified by gsd-ui-checker.

**Scope of this contract:** the three server rendered page families that the ExApp itself
serves during the authorization flow. Everything else in phase 3 is protocol, not UI.

1. **Consent page** (`GET /authorize` after the user is identified): who is asking, what is
   granted, approve or deny, explicit warning for a client that registered itself through DCR.
2. **Login Flow v2 interstitial**: hand off to the Nextcloud sign in page, wait state, success
   and failure state.
3. **AS error pages**: rejected client, expired or unknown code, DCR switched off, invalid
   redirect target, throttled, generic failure. Naming, never leaking internals.

**Out of scope (do not build here):** admin UI for the client allowlist and the DCR switch
(phase 4, CONTEXT deferred), per user token management in Nextcloud settings (EXAPP-02,
phase 4), data flow disclosure texts (phase 6).

## Platform Constraints (binding, from CONTEXT and the phase 2 topology)

| Constraint | Decision | Why |
|-----------|----------|-----|
| Rendering | Server rendered HTML from the Starlette/FastAPI app of the ExApp | The pages live in the ExApp, not in the Nextcloud frontend (D-33) |
| JavaScript | **Zero.** No framework, no bundler, no build step, no inline script | CSP friendly, auditable, no supply chain for a consent screen |
| Assets | No external fonts, no CDN, no image files, no icon package | Public authority target group, offline and air gapped installs, CSP `default-src 'none'` |
| CSS delivery | One `<style nonce="...">` block in `<head>`, per response nonce | Avoids a second PUBLIC manifest route for a stylesheet (D-38 keeps routes minimal) and avoids `'unsafe-inline'` |
| Icons | Inline `<svg>`, `currentColor`, `aria-hidden="true"`, 20x20, exactly three (warning, check, cross) | An icon package would be a dependency and a build step |
| Theming | Own neutral design, **no imitation of the Nextcloud look** | Security feature: the real password dialog is always Nextcloud's own page, our pages must never be mistaken for it |
| Sender identity | Every page carries the wordmark "MCP Connector for Nextcloud" plus the target instance host | The user must always see who is asking |
| Language | v1 renders **English**, consistent with `docs/client-setup.md` and `docs/exapp-install.md` | German column below is the reference for a later locale, not shipped code (vulture gate: no unused dict) |
| Text location | All user facing strings in one module, `src/mcp_connector/exapp/ui/strings.py`, one constant per string, no string literal in a template function | Makes the later locale a data change, not a rewrite |
| Responsiveness | Single column, `max-width: 560px`, fluid below that, no media query needed except one at 600px for page padding | The whole surface is one card on one screen |

### Required response headers on every HTML page of this phase

```
Content-Security-Policy: default-src 'none'; style-src 'nonce-{nonce}'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Cache-Control: no-store
Content-Type: text/html; charset=utf-8
```

`frame-ancestors 'none'` plus `X-Frame-Options` are not decoration: a framable consent page is
a clickjacked consent page. `Cache-Control: no-store` repeats the phase 2 lesson (pitfall 4,
the PHP proxy caches for 3600 seconds unless told otherwise) and now also protects a page that
carries a client name and a redirect target.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon to label gap, gap inside a badge |
| sm | 8px | Label to field, list item spacing, button icon gap |
| md | 16px | Default gap between blocks inside the card, card inner padding on narrow screens |
| lg | 24px | Card padding, gap between heading block and body block |
| xl | 32px | Gap between card sections, callout margin |
| 2xl | 48px | Card top margin below the wordmark bar |
| 3xl | 64px | Page top padding on screens wider than 600px |

Exceptions: none. Two derived values stay on the scale on purpose: minimum interactive height
**44px** (11 x 4, touch target) and content `max-width` **560px** (140 x 4).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Rules:

- Exactly these four sizes and exactly two weights (400, 600). No 300, no 700, no italics.
- URLs, client IDs and redirect targets render at 14px monospace, weight 400, with
  `overflow-wrap: anywhere` so a long redirect URI wraps instead of overflowing the card.
- One Display per page (the page question), one Heading per section, never a heading used
  purely for size.
- No text below 14px anywhere, including the footer line.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F6F7` | Page background, disabled surfaces |
| Secondary (30%) | `#FFFFFF` | The card, the callout body, the URL box |
| Accent (10%) | `#1F3A5F` | See reserved list below |
| Destructive | `#B3261E` | Error page icon and error heading only |

Supporting values (not part of the 60/30/10 split, all measured against their own background):

| Token | Value | On | Contrast |
|-------|-------|----|----------|
| Text primary | `#1A1A1A` | `#FFFFFF` / `#F5F6F7` | 16.9 : 1 / 15.9 : 1 |
| Text muted | `#5A6270` | `#FFFFFF` | 6.1 : 1 |
| Border | `#D5D8DD` | `#FFFFFF` | 1.4 : 1 (decoration only, never the sole signal) |
| Warning text | `#8A5A00` | `#FFF8E6` | 5.6 : 1 |
| Warning surface | `#FFF8E6` | page | callout background |
| Success text | `#1E6B3A` | `#FFFFFF` | 5.4 : 1 |

Accent reserved for: **(1)** the primary button fill (`Approve access`, `Continue to Nextcloud
sign in`), **(2)** the focus ring on every interactive element, **(3)** the wordmark bar rule
above the card, **(4)** inline text links. Nothing else. Never as a decorative background,
never on a badge, never on the deny button.

Deliberately **not** used: `#0082C9` and the rest of the Nextcloud brand palette. A page that
looks like Nextcloud teaches the user that a Nextcloud looking page can come from somewhere
else, and that is exactly the lesson this flow must not teach.

Colour is never the only signal:

- the DCR warning is a callout with a border, a warning icon and the literal word
  "Unverified client", not a yellow tint;
- the success state carries a check icon and the word "Connected";
- every error page carries a cross icon plus a heading that names the problem in words
  ("This link has expired", "This app is not allowed"), so the red is never the message;
- the deny button is distinguished from approve by fill and by label, not by hue alone.

## Screen Inventory

### S1: Sign in handoff (`GET /authorize`, no Nextcloud identity yet)

| Element | Content |
|---------|---------|
| Wordmark bar | "MCP Connector for Nextcloud" plus `cloud.example.com` (the configured public host, never the Host header) |
| Display | "Sign in to continue" |
| Body | "{client} wants to connect to your Nextcloud. Sign in at {host} first. This page never asks for your password." |
| Primary | Button "Continue to Nextcloud sign in" (link to the Login Flow v2 login URL, `target="_blank" rel="noopener noreferrer"`) |
| Secondary | Link "Cancel connection" (returns `access_denied` to the client) |
| Footer | "The password prompt is always Nextcloud itself. If any other page asks you for your Nextcloud password, close it." |

### S2: Waiting for sign in (same URL, poll state)

- Auto refresh through `<meta http-equiv="refresh" content="3">`. No JavaScript polling.
- Status line with `role="status"` and `aria-live="polite"`: "Waiting for your sign in at {host}."
- Manual fallback button "Check now" (a plain GET form) for browsers with meta refresh disabled.
- Secondary link "Start over" and "Cancel sign in".
- Timeout after the Login Flow v2 poll token expires: switch to E4 (see error pages), never
  refresh forever.

### S3: Consent (`GET /authorize` with identity, `POST /authorize` decides)

| Element | Content |
|---------|---------|
| Display | "Allow {client} to use your Nextcloud?" |
| Identity line | "You are signed in as {user} at {host}." |
| Warning callout | Only when the client registered itself through DCR and is not on the allowlist. Heading "Unverified client". Body: "This app registered itself automatically. Nextcloud has not verified it. Only approve it if you started this connection yourself." |
| Detail list | Definition list, `<dl>`: "App name" ({client_name}), "Sends you back to" ({redirect_uri}, monospace, full value, never truncated), "Client ID" ({client_id}, monospace) |
| Grant list | Heading "What this allows". Items: "Read your files, calendar, notes, contacts and Deck cards, exactly as far as your own account reaches"; "Create and change notes, calendar entries, Deck cards and files that do not exist yet"; "Nothing is deleted. The connector has no delete tools."; "Access ends when you revoke it in Nextcloud settings." |
| Primary | Button "Approve access" (accent) |
| Secondary | Button "Deny access" (white fill, `#1F3A5F` border and label) |
| Footer | "Approving does not share your password. The connector receives its own credential and never sees the password you typed at {host}." |

Interaction rules:

- Both buttons are `<button type="submit">` inside one `<form method="post">`, distinguished by
  `name="decision"` with values `approve` and `deny`. No JavaScript, no link that performs a
  state change (a GET must never grant anything).
- The form carries the anti forgery token as a hidden field, bound to the authorization request.
- **Initial focus is the heading, never the approve button.** A page that lands with the granting
  action focused turns a stray Enter key into a grant.
- Approve is not the last element in tab order by accident: order is heading, details, deny,
  approve. Deny before approve, so the safe action is reachable first.
- No auto submit, no countdown, no "remember my choice" in v1.

### S4: Result pages

| State | Heading | Body | Action |
|-------|---------|------|--------|
| Approved, client cannot be redirected back (out of band) | "Connected" | "{client} may now use your Nextcloud as {user}. You can close this window." | none |
| Denied | "Access denied" | "{client} did not get access. Nothing was shared. You can close this window." | none |

The normal approved case is a 302 back to the exact registered `redirect_uri` and renders no
page at all. A rendered success page appears only when there is nowhere to redirect to.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Approve access" (consent), "Continue to Nextcloud sign in" (handoff), "Check now" (wait state) |
| Secondary CTA | "Deny access", "Cancel connection", "Cancel sign in", "Start over" |
| Empty state heading | "Nothing to approve" |
| Empty state body | "This page only appears while an app is asking for access. Start the connection again in your assistant app." |
| Error state | Problem plus next step, never a stack trace, never an internal path, never a client secret. Full table below. |
| Destructive confirmation | The consent grant itself is the risk bearing action. It is gated by an explicit named button ("Approve access"), the warning callout for unverified clients, and focus that does not start on the button. No extra checkbox: the second line of defence is the admin allowlist (D-35), not friction that would break plug and play (SC 1, SC 2). Token revocation UI is phase 4. |

### Error pages (E1 to E7)

| ID | Trigger | Heading | Body | Action | HTTP |
|----|---------|---------|------|--------|------|
| E1 | Client not on the allowlist, or `allowed` flag revoked | "This app is not allowed" | "An administrator has not allowed {client} to connect to this Nextcloud. Ask your administrator to add it, then try again." | none | 403 |
| E2 | DCR switched off, unknown client | "Automatic registration is off" | "An administrator switched off automatic app registration on this Nextcloud. Ask your administrator to register {client} manually, then try again." | none | 400 |
| E3 | Authorization code expired, unknown or already used | "This link has expired" | "Authorization links are valid for a few minutes and can be used once. Start the connection again in your assistant app." | none | 400 |
| E4 | Login Flow v2 poll expired or was cancelled | "Sign in timed out" | "The sign in was not completed in time. Start the connection again in your assistant app." | Link "Start over" | 408 |
| E5 | `redirect_uri` unknown, not an exact match, or not https and not localhost | "This app cannot be sent back safely" | "The address {client} asked us to return to does not match its registration. For your safety nothing was shared. Start the connection again in your assistant app, and tell your administrator if it keeps happening." | none | 400 |
| E6 | Too many attempts (throttle, SC 5) | "Too many attempts" | "Wait {seconds} seconds and try again." (`Retry-After` header set on the same response) | none | 429 |
| E7 | Anything else, including store or cache unreachable (fail closed, D-37) | "Something went wrong" | "The connection could not be completed. Try again. If it keeps failing, an administrator can find the details in the app log under reference {ref}." | none | 500 |

Copy rules that the checker enforces:

- Every error names what happened **and** the next step. No bare "Invalid request".
- No OAuth error codes, no parameter names, no host names of internals, no token or code
  fragments, no PHP or Python trace in the body. `{ref}` in E7 is a random per response id that
  only correlates with a log line, it decodes to nothing.
- No blame ("you entered"), no apologies ("Sorry!"), no exclamation marks, no emoji.
- The word "password" appears exactly where it reassures: the connector never asks for one.
- Never "click here". Link text is the destination.

## Accessibility Contract

Target: WCAG 2.2 AA. Verified by review against this list, not by a tool alone.

- One `<h1>` per page (the Display line). Sections use `<h2>`. No heading levels skipped.
- Landmarks: `<header>` for the wordmark bar, `<main>` for the card, `<footer>` for the
  reassurance line. `lang="en"` on `<html>` (`lang="de"` once the locale exists).
- The consent detail list is a real `<dl>`, the grant list a real `<ul>`. No layout tables.
- Buttons are `<button>`, links are `<a>`. Never a `<div>` with a role.
- Focus ring: `outline: 3px solid #1F3A5F; outline-offset: 2px` on `:focus-visible`, on every
  interactive element. `outline: none` is forbidden anywhere in the stylesheet.
- Every interactive element is at least 44px high and 44px wide.
- The wait state announces through `role="status"` `aria-live="polite"`. Nothing else is live.
- Icons are `aria-hidden="true"` and always accompanied by their own text label.
- The page works at 200 percent zoom and at 320px width without horizontal scrolling; long
  URLs wrap with `overflow-wrap: anywhere`.
- Respect `prefers-reduced-motion`: there is no animation in this phase, so nothing to disable.
  No spinner, no pulse, no transition longer than 0ms on the meta refresh path.
- Dark mode: `prefers-color-scheme: dark` is **not** implemented in v1 and the pages force the
  light palette by declaring `color-scheme: light`. A half done dark mode on a consent screen
  produces unreadable warning callouts, which is worse than a light page at night.

## Component Inventory (what the executor builds)

| Component | File | Notes |
|-----------|------|-------|
| `page(...)` shell | `exapp/ui/layout.py` | `<!doctype>`, head with nonce style block, wordmark bar, main card, footer. Every page goes through it, so the security headers and the nonce have exactly one source |
| `button_primary`, `button_secondary` | `exapp/ui/layout.py` | Rendered as form submits only |
| `callout(kind, title, body)` | `exapp/ui/layout.py` | Kinds: `warning`, `error`, `success`. Icon plus title plus body, never colour alone |
| `detail_list(items)` | `exapp/ui/layout.py` | `<dl>`, monospace values, wrapping |
| Consent page | `exapp/ui/consent.py` | S1, S2, S3, S4 |
| Error pages | `exapp/ui/errors.py` | E1 to E7 from one table, one function |
| Strings | `exapp/ui/strings.py` | All user facing text, one constant per string |
| Icons | `exapp/ui/icons.py` | Exactly three inline SVG constants |

Escaping: every interpolated value (client name, redirect URI, user, host) is HTML escaped at
the single point where the template writes it. Client names and redirect URIs come from
attacker controlled DCR input and are the reason this rule is not negotiable. The rendered
client name is additionally truncated to 80 characters and stripped of control characters, so a
registration cannot fake extra page copy.
